What does this tool do?

This page helps you search for robot designs that meet one or more performance requirements. You define the robot and task, choose performance targets, and let the evolving-SVD optimizer change the design over multiple nonlinear iterations.

Four ideas to know first

Design variables. Physical quantities that describe the robot, including its link dimensions and distributed section sizes.

Performance metrics. Quantities such as travel time, structural frequencies, mass, and inertia-related measures.

Primary targets. Requirements that must be achieved or protected, such as travel time ≤ a limit or structural frequency ≥ a minimum.

Null-space objectives. Secondary goals that can be improved using design freedom that has little first-order effect on the protected targets.

First tutorial — run a simple search

  1. Leave the default robot and task values unchanged.
  2. Click Analyze starting design.
  3. Look at the Starting performance values. These are your baseline.
  4. Enable only Travel time as your first target.
  5. Keep the ≤ relationship and enter a target slightly below the current travel time.
  6. Leave the Null-space objectives unchecked for this first run.
  7. Keep Maximum iterations at 10 and leave the SVD step limit at its default.
  8. Click Run evolving-SVD target + null search.
  9. Use the Iteration history and View buttons to inspect the accepted designs.

How to read the main results

  • Travel ms — predicted motion time.
  • f1 / f2 — first and second flexible structural frequencies.
  • Mass kg — modeled structural mass.
  • σmin — the smallest active singular value of the local design-to-performance map.
  • Cond. — condition number; larger values indicate more uneven sensitivity across directions.
  • Error — remaining primary-target error.
  • Active — portion of the step used to satisfy primary targets.
  • Null — portion used for secondary objectives.
  • Step — total accepted design change for the iteration.

What is SVD?

SVD stands for Singular Value Decomposition. In this application it helps identify which combinations of design changes affect the selected performance metrics strongly, weakly, or almost not at all. Because that relationship changes as the robot changes, the SVD is recomputed throughout the search.

What is the null space?

Once important performance targets are protected, there can still be ways to change the robot without significantly disturbing those targets. Those locally redundant directions form the null space.

Example:

Primary target: Travel time ≤ 115 ms
Secondary objective: Minimize mass

The optimizer first works toward the travel-time requirement, then uses available null-space freedom to reduce mass while preserving the target.

Second tutorial — add a secondary objective

  1. Analyze the starting design.
  2. Enable Travel time as a primary target.
  3. Choose a modest improvement from the baseline.
  4. Under Null-space objectives, enable Mass.
  5. Leave it set to minimize with weight 1.
  6. Keep the null-space step fraction at 0.25 initially.
  7. Run the search and compare Travel time and Mass across iterations.

Useful controls

Tolerance is relative and entered as a percentage. A value of 1 means approximately 1%.

Maximum iterations limits the search length. Leaving it blank allows the solver to continue until convergence/stall, subject to the safety cap.

Maximum local SVD step limits how far the optimizer moves per local iteration. Smaller values are more conservative.

Null-space step fraction controls how much of the local step budget may be used for secondary goals while the primary targets are still being pursued.

Recommended beginner workflow

  1. Analyze the default design.
  2. Enable one target only.
  3. Ask for a modest improvement.
  4. Inspect the iteration history.
  5. Add one null-space objective.
  6. Then experiment with multiple targets and secondary objectives.

Important note

This is a design-exploration and research tool. Results depend on the mathematical and simulation models used and should be independently validated before physical construction, safety-critical use, or engineering certification.

Optional. These objectives are projected into the evolving null space of the enabled primary targets. Weights are relative; each projected direction is normalized before weighting.
0 = primary targets only; 1 = allow the null objective to use the full local step budget. Once all primary targets are satisfied, the solver can use the full trust region in the null space.

Search controls
